# Feature Specification: identity-svc 身份服务

**Feature Branch**: `feature/003-identity-svc`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "identity 身份服务：实现 IsleTalk 的账号与身份限界上下文，承接 002 架构中 identity-svc 的职责。包含：手机号注册登录与验证码、设备会话与多端管理、可选实名认证与信任等级、公开账号名与不可变内部账号 ID、资料可见性与陌生人添加开关。是首段切片（MVP）的第一个服务。"

## 承接关系

本 spec 是**服务级规格**，承接 `specs/002-wechat-style-chat` 的架构设计与「FR→服务承接表」中 identity-svc 的职责边界。上游 002 定义了产品级需求（85 条 FR）与 7 服务拆分；本 feature 把 identity-svc 的承接范围（002 的 FR-001~006、FR-049、FR-059~060、FR-069~078）细化为可独立实现、独立测试的服务级规格。**本 spec 不重复定义产品需求，只做服务级展开；冲突时以 002 与宪法为准。**

## Clarifications

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手机号注册并登录 (Priority: P1)

新用户用手机号完成注册，取得身份后直接进入使用；已有用户能登录、退出。

**Why this priority**: 身份是其他所有服务的前提——relationship 与 message 都以 identity 签发的身份为准。它是首段切片的第一块基石。

**Independent Test**: 在干净环境用手机号注册 → 校验验证码 → 设昵称 → 登录 → 退出，全程不依赖任何其他服务。

**Acceptance Scenarios**:

1. **Given** 一个未注册手机号，**When** 用户请求验证码并提交正确验证码完成注册，**Then** 系统创建账号并返回身份凭证，验证码仅可使用一次
2. **Given** 已注册用户，**When** 输入正确凭证登录，**Then** 登录成功并建立设备会话
3. **Given** 用户输入错误凭证，**When** 尝试登录，**Then** 登录失败，且不泄露"账号是否存在"与"密码是否错误"的区分
4. **Given** 用户不记得密码，**When** 通过手机号验证后重置密码，**Then** 重置成功且旧会话全部失效

---

### User Story 2 - 多端会话管理 (Priority: P1)

同一账号可多设备同时在线；用户能查看并远程下线自己的会话，改密后旧会话全部失效。

**Why this priority**: 多端一致（002 的 FR-003/005）是首段切片"消息在两端一致呈现"的基础，且改密全失效是账号安全底线。

**Independent Test**: 两台设备登录同一账号 → 查看会话列表 → 远程下线其中一台 → 改密后验证两台均失效，可独立验证。

**Acceptance Scenarios**:

1. **Given** 账号已登录设备 A，**When** 在设备 B 用同一账号登录，**Then** 两台设备的会话同时有效
2. **Given** 用户查看自己的会话列表，**When** 选择远程下线某设备，**Then** 该设备会话被撤销，其余会话不受影响
3. **Given** 用户修改密码，**When** 修改完成，**Then** 该账号全部既有会话在合理时间内失效
4. **Given** 用户退出登录，**When** 退出，**Then** 当前会话被撤销

---

### User Story 3 - 公开账号名与不可变标识 (Priority: P1)

用户设置一个系统保证唯一、可被搜索、可修改的公开账号名；系统同时分配一个不可变、不可搜索的内部账号 ID。

**Why this priority**: 公开账号名是"别人怎么找到你"的基础（002 的 FR-075~078），也是首段切片建立好友关系的前置。

**Independent Test**: 设置账号名 → 改名为未被占用的新名 → 验证旧名在保留期内不可被他人使用 → 验证内部 ID 不变，可独立验证。

**Acceptance Scenarios**:

1. **Given** 新注册用户，**When** 设置一个未被占用的公开账号名，**Then** 设置成功且该名字全局唯一
2. **Given** 用户已设置账号名，**When** 改为另一个未被占用且不在保留期内的名字，**Then** 改名成功，内部账号 ID 保持不变
3. **Given** 用户放弃某账号名，**When** 他人在保留期内尝试占用该名字，**Then** 被拒绝，且提示不泄露原持有者信息
4. **Given** 两名用户同时设置同一账号名，**When** 提交，**Then** 仅一人成功，另一人收到明确冲突提示

---

### User Story 4 - 资料与隐私可见性 (Priority: P2)

用户能设置昵称、头像、个性签名，并控制资料可见范围与"是否允许陌生人添加"。

**Why this priority**: 这是用户主动使用的资料能力（FR-004），但隐私开关（FR-049）关系到骚扰治理，是 P2 里影响最靠前的。

**Independent Test**: 修改昵称头像签名 → 调整可见范围为"仅好友" → 切换陌生人添加开关，逐项验证，可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户，**When** 修改昵称、头像、个性签名，**Then** 修改生效并对其他用户可见（受可见范围约束）
2. **Given** 用户将资料可见范围设为"仅好友"，**When** 非好友查看其资料，**Then** 看不到受限字段
3. **Given** 用户关闭"允许陌生人添加我"，**When** 陌生账号尝试发起好友申请，**Then** 该申请被拒绝
4. **Given** 用户设置界面语言，**When** 之后启动应用，**Then** 语言选择被记住并生效

---

### User Story 5 - 可选实名与信任等级 (Priority: P2)

用户可自愿提交身份信息完成实名以获得信任等级标识与更高使用额度；未实名的用户能使用全部功能。

**Why this priority**: 实名是可选增强而非使用前提（FR-069），其敏感个人信息属性要求单独同意、加密存储与可撤回（FR-070~074），属 P2 中合规面最重的。

**Independent Test**: 提交身份信息（含单独同意）→ 获得信任等级 → 撤回实名 → 信任降级且额度回落，可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户希望提升信任等级，**When** 在单独告知处理目的与保留期限并取得明示同意后提交身份信息，**Then** 实名成功并获信任等级标识
2. **Given** 用户未提交身份信息，**When** 使用应用，**Then** 可使用全部功能，不因未实名受限
3. **Given** 已实名用户，**When** 撤回实名，**Then** 身份信息按保留策略删除、信任等级降级、放宽额度同步回落
4. **Given** 身份信息采集，**When** 检查日志与对外接口，**Then** 身份信息不出现在日志、指标、追踪、错误响应或任何对外接口中

---

### User Story 6 - 注销与数据处置 (Priority: P2)

用户能主动注销账号；系统按既定保留策略处理其数据，并在界面明确告知。

**Why this priority**: 注销是账号生命周期终点（FR-006），涉及身份信息删除（FR-074）与数据保留合规，是上线前必须具备的底线。

**Independent Test**: 发起注销 → 二次确认 → 注销生效 → 该账号身份失效且会话全失效，可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户发起注销，**When** 二次确认并重新验证身份，**Then** 账号进入注销状态，全部会话失效
2. **Given** 注销前，**When** 系统展示数据处置说明，**Then** 用户能看到其数据（含身份信息）的保留期限与删除方式
3. **Given** 已注销账号，**When** 尝试登录或使用，**Then** 身份已失效，得到明确提示

---

### Edge Cases

- **验证码重放**：同一验证码 MUST NOT 可被两次使用；有效期与重发冷却由服务端时钟判定，MUST NOT 依赖客户端时间。
- **手机号是否已注册的枚举**：登录、注册、找回密码、验证码下发接口 MUST NOT 通过响应内容、错误码或提示区分"该手机号是否已注册"（对应 002 SC-037）。
- **账号名并发冲突**：两名用户同时占用同一账号名时 MUST 只有一人成功；MUST NOT 出现两个账号同时"拥有"同一名字的状态。
- **改名冷却与保留期**：改名受冷却期限制（默认 30 天）；放弃的名字进入保留期（默认 90 天），保留期内 MUST NOT 被他人使用。
- **实名提交中断**：提交过程中断（网络失败或中途退出）MUST NOT 产生"已实名"状态，MUST 允许重新提交，且 MUST NOT 残留半份身份信息。
- **撤回实名后的额度回落**：信任等级立即降级，放宽额度同步回落。
- **多端改密竞态**：改密与多端同时在线的竞态 MUST 最终收敛到"全部旧会话失效"，不出现某个旧会话继续有效。
- **注销与在途请求**：注销生效后，在途请求 MUST 得到明确失败，不得继续以已注销身份完成。
- **虚假身份信息**：因首段切片不做真实验证，用户可能提交虚假身份信息获取信任等级；该风险通过"实名不是使用前提 + 信任等级额度有限"控制，真实验证上线后 MUST 对存量已实名用户补验。
- **会话撤销的存储一致**：会话撤销需同步 Redis（热路径）与 MongoDB（持久事实），两者不一致时 MUST 以 MongoDB 为准并在 5 分钟内收敛，MUST NOT 出现已撤销会话继续通过鉴权。
- **验证码下发失败**：短信下发失败时 MUST 明确告知用户并可重新请求（受重发冷却约束），MUST NOT 静默失败或让用户误以为验证码已发送。

## Requirements *(mandatory)*

### Functional Requirements

**注册与登录**（承接 002 FR-001~003、FR-059~060）

- **FR-001**: 系统 MUST 支持手机号注册；验证码在有效期内仅可成功使用一次，有效期与重发冷却为服务端判定的可调参数。
- **FR-002**: 注册完成后用户 MUST 直接获得身份并登录使用，MUST NOT 需要人工审核。
- **FR-003**: 系统 MUST 支持密码登录与手机号验证码登录；登录失败时 MUST NOT 区分"账号不存在"与"密码错误"。
- **FR-004**: 系统 MUST 支持通过手机号验证后重置密码；重置成功后全部既有会话 MUST 失效。
- **FR-005**: 系统 MUST 支持退出登录与撤销当前会话。
- **FR-006**: 系统 MUST 对注册、登录、验证码下发实施频率限制与异常行为识别，刷号与暴力尝试 MUST 被自动阻断。
- **FR-007**: 系统 MUST 面向公开注册开放，MUST NOT 要求人工审批（除受邀内测通道外）。

**会话与多端**（承接 002 FR-003、FR-005）

- **FR-008**: 同一账号 MUST 支持多设备同时在线；每台设备有独立会话标识。
- **FR-009**: 用户 MUST 能查看自己的会话列表并远程下线指定会话。
- **FR-010**: 修改密码、注销账号、高风险操作后，相关会话 MUST 在 5 分钟内全部失效（默认值，可调）。
- **FR-011**: 会话 MUST 记录最近活跃时间；被撤销的会话 MUST 立即拒绝后续请求。

**标识与账号名**（承接 002 FR-075~078）

- **FR-012**: 系统 MUST 为每个用户分配全局唯一、不可变的内部账号 ID；该 ID MUST NOT 展示为可搜索的公开标识，MUST NOT 提供任何修改途径。
- **FR-013**: 用户 MUST 能设置一个独立的公开账号名；系统 MUST 保证账号名唯一，冲突 MUST 立即报错并提示，MUST 校验保留词。
- **FR-014**: 用户 MUST 能修改公开账号名；此修改 MUST NOT 影响内部账号 ID；改名 MUST 受冷却期限制（默认 30 天）。
- **FR-015**: 用户放弃的账号名 MUST 进入保留期（默认 90 天），保留期内 MUST NOT 被其他用户使用；保留期到期后 MUST 自动释放回可占用状态；占用失败提示 MUST NOT 泄露原持有者信息。
- **FR-016**: 系统 MUST 支持按公开账号名精确搜索用户；MUST NOT 提供按手机号搜索用户的能力，手机号 MUST 仅用于验证码验证身份。

**资料与隐私**（承接 002 FR-004、FR-049）

- **FR-017**: 用户 MUST 能修改昵称、头像、个性签名。
- **FR-018**: 用户 MUST 能控制资料可见范围（如公开 / 仅好友 / 私密）与是否允许陌生人添加自己。
- **FR-019**: 系统 MUST 支持简体中文与英文两种界面语言；用户选择 MUST 被记住并在后续启动生效；验证码短信、错误提示、注销告知等非界面文案 MUST 同样支持两种语言。

**实名与信任**（承接 002 FR-069~074）

- **FR-020**: 用户 MUST 能自愿提交身份信息完成实名登记；系统 MUST 收集并加密存储身份信息，MUST NOT 比对权威数据源做真实验证；信任等级按"已提交"授予；未实名用户 MUST 能使用全部功能，实名 MUST NOT 成为任何功能的前提。
- **FR-021**: 采集身份信息前 MUST 以单独同意取得明示同意，并事先告知处理目的、范围、保留期限与后果。
- **FR-022**: 身份信息与手机号 MUST 静态加密/哈希存储，MUST NOT 以明文出现在日志、指标、链路追踪、错误响应与任何对外接口中，展示时 MUST 脱敏；运营人员查看未脱敏身份信息 MUST 单独授权且留痕。
- **FR-023**: 身份信息 MUST 仅用于实名与信任等级目的，MUST NOT 用于内容推荐、画像外销或任何未经单独同意的用途。
- **FR-024**: 用户 MUST 能查看自己的实名状态并撤回实名；撤回后 MUST 删除身份信息、信任等级降级、放宽额度同步回落。
- **FR-025**: 身份信息 MUST 有明确保留期限与到期删除机制；用户注销账号时 MUST 按该机制处理并告知用户。
- **FR-026**: 实名带来的信任等级 MUST 派生为受限维度上更高的使用额度（消息发送频率、新增好友数、创建群聊数等），具体额度 MUST 在 plan 论证并对用户可见。

**注销与数据处置**（承接 002 FR-006、FR-074）

- **FR-027**: 用户 MUST 能主动注销账号；注销 MUST 要求二次确认与重新验证身份。
- **FR-028**: 注销后账号 MUST 进入失效状态、全部会话失效；系统 MUST 按保留策略处理用户数据并在界面明确告知处理方式。

**对外服务能力**（供 relationship / message 等内部服务调用，见 contracts/proto/identity/v1/identity.proto）

- **FR-029**: 系统 MUST 提供按内部 ID 查询用户的内部接口；返回字段 MUST 不含手机号明文与身份信息。
- **FR-030**: 系统 MUST 提供"校验用户是否可用"的内部接口，供消息授权使用；响应 MUST NOT 区分"不存在"与"被封禁"以外的多余信息（防枚举）。

### Key Entities

- **用户账号**：身份载体。属性含不可变内部账号 ID、公开账号名、手机号（哈希/加密，不落明文）、昵称、头像、个性签名、可见范围、陌生人添加开关、注册与注销状态、风控处置状态。
- **设备会话**：一次登录实例。属性含会话标识、设备标识、登录时间、最近活跃时间、是否被撤销。
- **界面语言偏好**：用户选择的界面语言。属性含语言标识、来源（跟随系统 / 用户指定）、更新时间。
- **实名信息**：自愿提交的身份信息。属性含身份标识、登记状态（待提交 / 已提交 / 已撤回）、提交时间、保留期限。
- **信任等级**：由实名登记派生的用户属性。属性含等级、对应额度、放宽项。首段切片按"已提交"授予，不基于真实验证。
- **账号名占用**：公开账号名的分配与保留记录。属性含账号名、占用者、释放时间、保留截止时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户完成"注册 → 设置昵称与账号名 → 登录使用"全流程的成功率 ≥ 99%，无需人工协助。
- **SC-002**: 验证码在有效期内仅可用一次的校验通过率 100%（重放 MUST 被拒绝）。
- **SC-003**: 系统 MUST NOT 通过响应内容、错误码或提示区分"该手机号是否已注册"；抽样验证两种情形响应一致。
- **SC-004**: 修改密码后，旧会话全部失效的完成率 100%（合理时间窗口内）。
- **SC-005**: MUST NOT 出现两个账号同时占用同一账号名；账号名唯一性校验通过率 100%。
- **SC-006**: 按公开账号名精确搜索命中目标用户的成功率 ≥ 99%。
- **SC-007**: 身份信息在日志、指标、链路追踪、错误响应与对外接口中的出现次数为 0（抽样验证）。
- **SC-008**: 采集身份信息前取得单独同意的比例 100%；用户查看与撤回实名状态的入口 100% 可用。
- **SC-009**: 用户撤回实名或注销账号后，身份信息在 30 天内完成删除或不可逆处理（法定留存除外，已告知用户）。
- **SC-010**: 注册与登录接口在遭受高频试探时，异常行为被自动阻断的成功率 100%。

## Assumptions

- **上游承接**：本服务的职责边界以 002 的「FR→服务承接表」为准；本 spec 展开的 FR 与 002 对应条目冲突时，以 002 与宪法为准。
- **登录方式**：主为密码登录，辅为验证码登录；密码强度与 Argon2id 参数遵循宪法 E 组（本 spec 不重复）。
- **验证码参数**：有效期与重发冷却为服务端可调参数，默认值（如 5 分钟有效、60 秒冷却）在 plan 锁定。
- **账号名参数**：冷却期默认 30 天、保留期默认 90 天（承接 002 research R-8）。
- **实现语言与工具链**：Go + gofmt/golangci-lint/go vet/go mod/testify/go test -cover/buf（已登记于宪法 v2.7.0）；本 spec 不绑定实现细节。
- **存储**：MongoDB（identity 独占 database，集合带 `identity` 前缀）；Redis 承载会话令牌与会话状态、限流（非唯一事实来源）。
- **对外接口**：客户端 ↔ identity 走统一信封（见 002 contracts/envelope.md）；服务间走 gRPC（见 002 contracts/proto/identity/v1/identity.proto）。
- **短信与推送**：验证码经云短信服务商下发，本地开发用 mock（承接 002 research R-6）。
- **实名验证方式**：首段切片实名登记为"收集 + 加密存储"，MUST NOT 比对权威数据源做真实验证；信任等级按"已提交"授予。真实验证（第三方 API / 人工审核 / OCR）留待"转为强制实名"的触发条件达成时再上（承接 002 Assumptions 的实名触发条件）。
- **端到端加密**：不在本期范围（宪法 G 组未触发）；本服务以服务端可读为前提，隐私说明如实告知。
